# UI 重设计方案(三版)

设计稿:`docs/ui/ui-A-console.png` / `ui-B-feed.png` / `ui-C-list.png`(对比图 `ui-compare.png`)

## 现状的三个问题

1. **首屏看不到关键信息**。现在打开面板是先看到「运行」卡片的一排开关,"今天发了几个 / 下一轮几点 / 还有谁没发"要往下翻才看得到。
2. **目标是一张列表卡,不是一个"人"**。8 个好友的今日状态(已发/待发、火花天数)在现有卡片里只能读一行文字。
3. **视觉偏"演示感"**。液态玻璃 + 22pt 圆角 + 大卡片,单次打开好看,每天用好几次会觉得重。

## 方案 A · 控制台(Console)

**主张:打开就是为了"看一眼 + 按一下"。**

- 首屏三件事:环形进度(3/8 今日已发)、下一轮时间、一键「立即续火花」。
- 下面是紧凑设置行(总开关/目标数/间隔/定时),一屏放下全部高频操作。
- 底部 4 tab(状态/目标/外观/日志)保留,状态 tab 为默认。

改动落点:新增 `SparksRingGauge` + `SparksActionButton`,`buildSettingsTab` 拆成 `buildStatusTab` / `buildSettingsTab`,复用现有 `SparksGlassCard` 作为行容器。约 350–450 行,不动引擎。

## 方案 B · 目标卡片流(Feed)

**主张:以"人"为中心,一眼看出谁今天还没发。**

- 顶部筛选胶囊:全部 / 待发 / 已发。
- 每个目标一张卡:头像 + 昵称 + 火花天数(单聊/群聊)+ 右侧状态 chip。
- 右下 FAB「立即续火花」,底部保留 tab。

改动落点:新增 `SparksTargetCard`,替换现有「最近聊天」+「单独设置」两张卡;目标列表页从表单式改成滚动卡片流。需要给目标模型补上「火花天数」(从会话模型的扩展字段取,取不到就显示"—")。约 500–700 行,含一次数据模型扩展。

## 方案 C · 极简清单(List)

**主张:系统原生味,零装饰,每天都在点的东西不该有玻璃。**

- iOS 分组列表:白色卡片 + 细分割线 + 12pt 圆角,+ 每段一个小标题。
- 顶部导航:关闭 / 续火花 / 日志;底部一行状态文字。
- 材质开关(液态玻璃/玻璃/磨砂)在这套里直接下线。

改动落点:新增 `SparksGroupedList` + `SparksListRow`(switch/value/chevron 三种),`SparksGlassCard` 的用法批量替换。约 450–550 行,**纯替换、不碰业务逻辑,风险最低**。

## 三版共同的落地方式

- 新增 `cfg.uiStyle`(0=现状 / 1=Console / 2=Feed / 3=List),在面板「外观」里切换,跟材质(0/1/2)平级。
- 只换"外壳":卡片、行、按钮、tab 四类视图;引擎、配置、发送逻辑零改动。
- 建议按版本推进:先落一版验真机视觉,再叠第二版,不要把三套一起塞进去一次 CI。
