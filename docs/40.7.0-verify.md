## 分析方法

主可执行文件 `Payload/Aweme.app/Aweme` 只有 276,080 字节(薄壳),抖音的全部
Objective-C 类都在 `Payload/Aweme.app/Frameworks/AwemeCore.framework/AwemeCore`
(解压后 725,614,592 字节,thin arm64)。

在该二进制上导出两个 ObjC 元数据段:

| 段 | 字符串数 |
|---|---|
| `__TEXT,__objc_classname` | 172,758 |
| `__TEXT,__objc_methname` | 1,453,494 |

再逐个类解析 `__objc_classlist` → `class_t.data` → `class_ro_t.baseMethodList`,
判断**方法是否由该类自身实现**(不是从超类继承的)。这一步是硬要求,原因见
下面「三个坑」的第 1、2 条。

复跑:`python tools/verify_ipa.py <抖音.ipa>`(退出码 0 = 全部通过)。

## 二、40.7.0 上的三个坑(已修)

### 1. `AWEIMMessageListSendMessageComponent` 不实现 `-init`

该类的 method list 里**没有 `init`**(继承自超类)。旧代码写的

```objc
%hook AWEIMMessageListSendMessageComponent
- (instancetype)init { id r = %orig; [[SparksEngine shared] noteComponent:r]; return r; }
%end
```

对"本类未实现"的方法做钩子,替换会落到**超类的 Method** 上 —— 等于 hook 了
全 App 的 `init`;而 `noteComponent:` 不做类型判断,于是任意对象都会被当成发送
组件塞进引擎,后面 `sendMessage:...` 一调就崩。

处理:v2.16.0 删除该钩子。组件捕获由三条路覆盖:组件中心 `addComponent:` /
`addComponents:` / `setComponents:` + `componentDidMounted:` / `setDataService:`
+ VM 组件中心兜底。

### 2. `AWESettingPageBaseController` 不实现 `viewDidLoad`

同类问题。40.7.0 里设置首页已经换成 `AWESettingsTableViewController`
(`shouldUseDUXNavigationBar` 返回 `YES`,系统 `rightBarButtonItem` 不再渲染)。
旧代码对 `AWESettingPageBaseController` 直接 hook `viewDidLoad`,补丁会落到
`UIViewController` 链上,导致任意导航栈首页被塞一个火焰按钮。

处理:v2.16.0 改为运行期判定 —— `class_copyMethodList` 扫该类**自身**实现,
有才 `%init` 该钩子组,没有就打一行日志跳过。老版本(40.6.0)入口仍然保留。

### 3. 语音的 `duration` / `averagePowerArr` 挂错了类

| 类 | `duration` | `averagePowerArr` |
|---|---|---|
| `IESIMSendAudioInputContext` | ❌ 无 | ❌ 无 |
| `AWEIMMessageAudioContent` | ✅ `q16@0:8`(毫秒) | ✅ `@16@0:8` |

旧代码把这两个字段直接 `setValue:forKey:` 到音频输入上下文上,会抛
`NSUnknownKeyException`,被外层 `@try` 兜住后整条语音发送失败,只报一句
"context 组装异常"。

处理:v2.16.0 改为构造 `AWEIMMessageAudioContent` 挂到 `messageContent`;并把所有
字段写入换成 `SpSetKV()` 安全壳 —— 单字段失效只打一行日志,不再废掉整条消息。

## 四、遗留风险(未在真机上验证)

- 本次复核是**静态**的:能保证钩子挂在真实存在、且由该类自身实现的方法上,
  不能保证发送流程在 40.7.0 的运行时时序里同样成立(组件注册早于会话绑定、
  路由被拒等)。这些仍由 v2.15.0 的分阶段等待 + 补发队列兜底。
- `AWEIMSendAttachmentController` 的媒体管线还有 `sendAssets:...` /
  `forwardSendAttachmentMessage:...` 等同族入口,插件只钩统一入口
  `sendAttachmentMsgWithContext:completion:`;若某版本媒体发送绕过它,需要补钩。
- 自动发消息本身有风控风险,与版本无关。
